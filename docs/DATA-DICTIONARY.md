# 数据字典

- run_id：规则版本与输入 SHA-256 前 12 位组成的稳定批次标识。
- line_no：从 1 开始的物理来源行号，不因隔离或排序改变。
- business_key：本项目声明的业务唯一键，始终按字符串存储。
- reason_code：隔离原因的稳定英文编码。
- accepted：进入业务计算的记录数。
- quarantined：保留证据但不参与业务计算的记录数。
- 数值：金额、税额、用量和权重使用 Decimal；对外序列化为字符串。
- 时间：存储为带偏移的 ISO 8601，分桶使用半开区间。
- 空值：缺失键、空串和业务哨兵分别记录。
- 幂等：完整输入字节与规则版本相同则复用 run_id，不新增结果。
- 营销记录：以 marketing_carrier + marketing_flight_no 唯一标识，跨批次重复键与值冲突只隔离，不覆盖。
- 承运方声明：operating_carrier 与 operating_flight_no 必须成对出现；共享关系只来自该声明。
- group_id：由声明键（实际承运人、实际航班号、日期、航线）哈希得到，跨批次稳定。
- 归并航段：一个共享组在归并状态下只占一条实际航段；营销记录按来源逐条保留。
- 来源冲突：同一声明键下时刻声明不一致；冲突时进入待裁决，不按相同时刻猜测归属。
- 裁决版本：每次裁决、补偿、成员变化推进 version；旧版本请求返回 VERSION_CONFLICT。
- op_id：补偿的稳定操作标识，重试与中断恢复都复用它，保证不重复扣增。
- 补偿步骤：SNAPSHOT → SPLIT → RECOMPUTE → SETTLE；每步落库，恢复从未完成步骤继续。
- 对账：营销记录 = 实际航段 + 被归并吸收 + 未结算；未结算必须全部是待裁决，重复计入必须为零。
